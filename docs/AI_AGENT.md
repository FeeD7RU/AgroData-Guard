# Локальный ИИ-агент AgroData Guard

Агент использует Qwen3 через Ollama на компьютере пользователя. Модель сама выбирает
инструменты, получает факты из SQLite, продолжает расследование по их результатам
и формулирует ответ. Это LLM с циклом вызова инструментов, а не шаблонный текст
поверх статистических правил. Облачный API, ключ и оплата запросов не нужны.

## Запуск на Windows

Из папки проекта:

```powershell
.\start-local-agent.ps1
```

Скрипт использует portable Ollama в `.runtime/ollama` либо установленную Ollama.
Если обе отсутствуют, загружает официальный архив v0.40.6 и проверяет SHA-256.
Запускает Ollama на `127.0.0.1:11434` и скачивает `qwen3:14b`, если модели ещё нет.
Затем запускает веб-приложение с демо. Откройте http://127.0.0.1:8000 → «ИИ-агент».

Первая загрузка: runtime около 1,47 ГБ плюс модель около 9,3 ГБ; для распаковки нужен
дополнительный запас места. Дальнейшие запуски используют сохранённые файлы.
После скачивания модель работает без интернета. Вычисления используют GPU/CPU и электричество.

Для менее мощного компьютера:

```powershell
.\start-local-agent.ps1 -Model qwen3:4b
```

`-NoDemo` запускает без симулятора, `-SetupOnly` только готовит модель.
Если PowerShell блокирует локальный скрипт, его можно разово запустить командой
`powershell -NoProfile -ExecutionPolicy Bypass -File .\start-local-agent.ps1`.
Это не меняет системную политику выполнения скриптов.

При уже установленной и запущенной Ollama:

```powershell
ollama pull qwen3:14b
$env:AGRO_LLM_MODEL = 'qwen3:14b'
.\.venv\Scripts\python.exe -m agroguard.cli serve --demo
```

Приложение по умолчанию обращается только к `http://127.0.0.1:11434`.
`AGRO_OLLAMA_URL` позволяет задать localhost или host.docker.internal для локального
Docker Desktop. Произвольные внешние адреса отвергаются. Облачные имена моделей
и remote-model metadata отвергаются; у модели должна быть capability `tools`.
Docker-путь требует отдельной проверки доступности host Ollama из контейнера.

## Что спросить

* «Проверь последние данные датчиков. Что требует внимания?»
* «Разбери аномалию с ID …: это выброс или реальное изменение температуры?»
* «У этого датчика слишком много тревог. Проверь историю и объясни возможные причины».
* После ответа: «Какие факты подтверждают эту гипотезу?»

В интерфейсе видны ответ, предложения, реальные аргументы и результаты инструментов.
Карточка предложения открывает существующий экран ручной проверки. Решение не
применяется автоматически: пользователь видит текущую версию записи и выбирает действие.
Разговор можно продолжить или начать новый; история сохраняется в SQLite.

## Устройство

`agent.py`: провайдер Ollama и Investigator. Цикл: запрос → model tool_calls →
валидация → доменный инструмент → tool-result → следующий запрос модели → итог.
Используется native `/api/chat`, `stream=false`, `think=false`. HTTP здесь —
внутренний транспорт между двумя локальными процессами, без облачного сервиса.

`agent_tools.py` предоставляет шесть инструментов:

| Инструмент | Назначение |
|---|---|
| list_sensors | Каталог, по 30 датчиков с пагинацией |
| list_anomalies | Поиск аномалий с пагинацией, фильтром датчика и отсутствия ручного review |
| inspect_sensor | Последние 1–120 измерений по event time, статистика только этого окна |
| inspect_anomaly | Evidence, policy, версия, 10 review, до 12 исходных точек до и после события, рассчитанные медиана/MAD и изменения значений |
| get_analysis_rules | Текущие настройки и известные ограничения алгоритмов |
| propose_review | Подготовка предложения для предварительно изученной актуальной версии |

Произвольные SQL, команды ОС, сеть и запись измерений модели недоступны.
Контекст аномалии привязан к её времени, даже если событие старое. Следующие точки
явно помечены как ретроспективные данные: исходный детектор их не видел.
Отсутствие следующей точки представлено null, а не признаком восстановления.
Расчёты по исходным значениям отображаются отдельно от текста модели. Они не
доказывают причину сбоя: локальная базовая линия тоже может содержать ошибки.
Перед завершением расследования код требует историю датчика, а при подготовленном
предложении — чтение правил. После каждого набора вызовов trace сохраняется в БД,
поэтому ошибка следующего запроса к модели не теряет уже полученные свидетельства.
В форме есть отдельный режим «Подготовить рекомендацию для ручной проверки»
(`prepare_review: true` в API). В этом режиме отсутствие сохранённого предложения
не позволяет завершить запрос успешно: модель получает требование продолжить,
а при исчерпании бюджета возвращается явная ошибка. Обычный вопрос может завершиться
без предложения. Этот режим не применяет исправления автоматически.
Approve может рекомендовать только уже сохранённое предложенное значение.
Нельзя подготовить предложение для неизвестной, нормальной или уже изменённой
после осмотра записи. Это проверяется кодом независимо от ответа модели.

До 7 обращений к модели и 8 инструментов за запрос, до 2048 выходных токенов за
обращение; контекст Ollama — 32768 токенов. При росте контекста или приближении
лимита шагов инструменты отключаются для итогового ответа. Дополнительно действует
лимит 56000 символов передаваемой истории: слишком большой результат инструмента
заменяется явной ошибкой с предложением запросить меньше наблюдений. Временной бюджет 300 с
проверяется между шагами; сетевой timeout до 120 с. Один запрос агента одновременно
на процесс API. Ingestion продолжает работать независимо от ожидания модели.

Таблица `agent_runs` хранит вопрос, ответ, модель, parent ID, статус, журнал
инструментов, предложения и счётчики токенов. Контекст продолжения — до трёх предыдущих
вопросов и ответов (до 4000 символов каждого ответа); инструменты снова читают актуальные данные. Скрытые рассуждения
не сохраняются. Новая таблица создаётся дополнительно, существующие raw/review
и schema revision 1 совместимы и не переписываются.

## Ограничения

LLM может ошибиться в интерпретации и причине сбоя. Результаты инструментов помогают
проверить ответ, но не доказывают его правильность. Снижение FP в baseline-v2 не
является оценкой качества Qwen. Агент не обучается автоматически на review, не
запускается на каждом измерении и не выполняет бесконечный фоновый мониторинг.
Разговор запускает пользователь; внутри него модель выбирает следующие действия.

Raw metadata и имя reviewer в инструменты не передаются. Комментарии review
считаются недоверенными данными. Ответы и trace в браузере выводятся с HTML-экранированием.
Доступ к истории защищён тем же API_KEY, что остальные API; отдельных пользователей
и изоляции диалогов между пользователями пока нет. Если процесс аварийно завершён,
незавершённая запись может остаться со статусом running; её можно повторить.

Ctrl+C останавливает веб-сервер. Ollama, запущенная скриптом, остаётся доступной
локально; веса выгружаются из памяти после периода бездействия (`keep_alive=10m`).
Журнал: `.runtime/ollama.stderr.log`. Runtime и модели исключены из git.
