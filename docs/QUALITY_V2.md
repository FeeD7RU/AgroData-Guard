# Качество анализа baseline-v2

Проверено 7 октября 2026. Цель: сократить ложные тревоги, сохранив обнаружение
неисправностей на контролируемых сценариях. Версия применяется к новым измерениям;
старые анализы и ручные решения не пересчитываются.

## Изменения

* Возврат после одиночного выброса не считается вторым rate-сбоем, если значение
  вернулось в устойчивый диапазон и перед выбросом были три стабильные точки.
  Другие детекторы продолжают проверять это значение. Серия шумовых скачков
  не получает такое исключение.
* Trend сравнивает недавний наклон с предшествующим, учитывая реальные timestamp.
  Длительный равномерный прогрев сам по себе больше не считается началом drift.
* Временные правила обрывают контекст после разрыва более трёх интервалов cadence.
  Null не может скрыть длинный разрыв. Missing и физические границы действуют всегда.
* Пороги вынесены в проверяемую конфигурацию и сохраняются в snapshot анализа.
* Ingestion и benchmark вызывают общий QualityEngine. В интерфейсе появился раздел
  «Агент целиком» с FP/FN, precision/recall, нагрузкой на review, coverage и ошибками
  предложенных коррекций, включая предложения для здоровых точек.

## Методика

Для каждого seed используются десять сценариев: здоровый шум, устойчивый прогрев,
суточный цикл, spike, noise, stuck, bias, drift, перерыв сообщений и явные missing.
Обычно 160 точек, суточный цикл — 360 точек с cadence 10 минут. Первые 48 точек —
прогрев. Решение видит только прошлые наблюдения; разметка и чистые значения
используются после replay для вычисления метрик. Ручные review не имитируются.

`previous_rules` — тот же engine с отключёнными тремя новыми правилами; это
воспроизведение прежних эвристик, а не запуск архивной сборки. На основном наборе
уточнялась защита от ложного восстановления внутри шумовой серии. Затем правила
зафиксированы и проверены на дополнительных seed без дальнейшей подстройки.
Это новые реализации шума в тех же семействах сценариев, не новый реальный датасет.

## Воспроизведение

```powershell
.\.venv\Scripts\agroguard.exe evaluate --seeds 11,29,47,83,101 --output artifacts/quality
.\.venv\Scripts\agroguard.exe evaluate --seeds 211,307,419,523,631 --output artifacts/quality-holdout
```

Каждая папка содержит `comparison.json` с truth, конфигурацией и подробными
результатами, а также `comparison.md`. Артефакты не входят в git.
Полный автоматический suite: 100 passed, включая проверку совпадения replay с API/БД.

## Что осталось

Суточная периодичность и загрязнение raw-окна после длительного bias всё ещё
вызывают ложные тревоги. После разрыва статистике требуется новый прогрев:
in-range bias сразу после восстановления может остаться незамеченным.
Для следующего этапа нужны сезонная модель, обработка восстановления после bias
и размеченные реальные истории нескольких датчиков. Confidence пока является
эвристической оценкой, не калиброванной вероятностью. Автокоррекция по умолчанию выключена.
